## 채울 항목

| 항목 | 내용 | 상태 |
|---|---|---|
| **입력** | `ssot.md` 의 `INV-*`(불변식 7) · `DOD-*`(완료기준 12) · `REQ-N-*`(비기능 9) | ⏳ |
| **자동 검증** | `npm test` · `npm run build` · TypeScript 에러 0 | ⏳ |
| **하네스 검증** | `npm run verify:harness` — 보호 경로가 승인 없이 바뀌면 exit 1 (`ssot.md` §0.6) | ✅ 있음 |
| **수동 검증** | 자동화 수단이 없는 항목을 어떻게 볼 것인가 (`DOD-10` 반응형, `REQ-N-05` 한글 IME 등) | ⏳ |
| **증거** | 무엇을 남길 것인가 (`docs/screenshots/` 관례 재사용?) | ⏳ |
| **판정 기록** | 결과를 어디에 쓸 것인가 — `ssot.md` §0.4 구현상태 갱신 규칙 | ⏳ |
| **실패 시** | 구현 루프로 되돌리는 경로 | ⏳ |
| **권한** | `ssot.md` §0.6 — 검증 스크립트는 **실행만.** `scripts/verify-*.ts` 와 통과 기준 자체는 고치지 않는다 | ✅ 확정 |

> **통과 기준을 낮춰서 초록 불을 만들지 않는다.** 스크립트나 기준을 고쳐야 한다고 판단되면 **정책 변경**이므로 사람 승인을 받는다.
> `tests/**` 는 작성·수정할 수 있으나, **테스트가 무엇을 전제하는지는 사람이 검토한다** — 전제가 틀리면 초록 불이 거짓말이 된다.

## 먼저 메워야 할 공백

`ssot.md` §5.1에서 가져온 것:

- **자동 테스트 0** — `REQ-F-01` `REQ-F-02` `REQ-F-03` `REQ-F-08` `REQ-F-09` `REQ-F-11`
- **완료기준에 테스트 없음** — `DOD-01` `DOD-08` `DOD-09` `DOD-10` `DOD-11` `DOD-12`
- **비기능 전부 자동 검증 수단 없음** — `REQ-N-03`~`REQ-N-07`
- `INV-01`~`INV-07` 은 테스트에 매핑되어 있으나 **실제 통과 여부는 미확인**

## 선행 정리

- `RESOLVED-02` — 검증 기준이 `01 §7`(DoD) · `06 §9`(불변식) · `07 §2`(QA)에 삼중으로 존재한다. **계획 문서 ↔ 요구사항 → 요구사항**(`ssot.md` §0.5)이므로 `DOD-*` 가 기준이고 `07 §2` 는 실행 절차로 종속된다. 판정이 갈리면 `DOD-*` 를 따른다
- `OPEN-02` — 현재 구현상태는 파일 존재 여부로만 판정한 잠정값이다. 이 루프의 첫 결과로 재판정한다
- `ESCALATE-*` — 사람 판단 대기 항목은 **통과/실패를 판정하지 않는다.** `차단` 으로 보고한다
