> 규범 사양은 [`01-ssot.md`](./01-ssot.md) 에 있다.

## 채울 항목

| 항목 | 내용 | 상태 |
|---|---|---|
| **입력** | `01-ssot.md` 의 `REQ-F-*` · `ARCH-*` · `RULE-*` · `OOS-*` | ⏳ |
| **1회 실행 단위** | 어느 단위로 끊어 돌릴 것인가 (요구사항 1건? 마일스톤 1개?) | ⏳ |
| **출력** | 변경된 파일 목록 · 근거가 된 SSOT ID | ⏳ |
| **종료 조건** | 무엇을 만족하면 그 반복을 끝난 것으로 보는가 | ⏳ |
| **금지** | `OOS-*` 를 넘어서는 구현. 범위를 넓히려면 SSOT를 먼저 고친다 | ✅ 확정 |
| **중단 조건** | 작업 지시가 요구사항 · 아키텍처 · 하네스 규칙과 충돌하면 **실행하지 않고 사람을 부른다** (`01-ssot.md` §0.5) | ✅ 확정 |
| **차단 목록** | `ESCALATE-*` 에 걸린 항목은 사람이 기준을 고칠 때까지 손대지 않는다 | ✅ 확정 |
| **권한** | `01-ssot.md` §0.6 — `src/**` 은 **Issue 범위 안에서만**, `tests/**` 은 작성·수정 자유, `docs/**` 은 **읽기 전용** | ✅ 확정 |
| **Issue 범위의 정의** | 무엇이 "범위 안"인가. `.github/ISSUE_TEMPLATE/maintenance.yml` 이 6개 항목을 요구한다 — 그 틀을 그대로 쓸지 | ⏳ |
| **루프 횟수** | [`03-loop.md`](./03-loop.md) `LOOP-01`~`06` 이 정한다 — 1회의 정의 · 기본 3회 · 즉시 중단 조건 | ✅ 확정 |
| **검증과의 연결** | 루프 안에서 `npm run verify` 를 돌린다. 방법은 [`02-verification.md`](./02-verification.md) | ✅ 확정 |

> **범위 밖 개선은 하지 않는다.** 발견하면 고치지 않고 보고한다 (§0.6 「Issue 범위 안에서 수정」).
> 최종 승인은 사람이 한다 — 이 루프는 변경을 **제안**하는 단계까지다.

## 첫 작업 후보

`01-ssot.md` §6.3 `GAP-*` — **충돌이 아니라 할 일**이므로 사람 호출 없이 진행할 수 있다:

## 착수 전 차단 확인

`01-ssot.md` §6.1 `ESCALATE-02` `05` `06` 은 **사람 판단 대기**다:

- `ESCALATE-06` — `prisma/schema.prisma` 의 소유권 미정. **아키텍처로 판정되면 AI 는 스키마를 고칠 수 없다.** `GAP-01`(실사 조정)이 여기 걸린다
- `ESCALATE-02` — 개념 모델 7개 vs 실제 9개. 데이터 모델 문서를 건드리는 작업은 여기에 걸린다
- `ESCALATE-05` — `05-design.md` 의 문서 등급 미정

> `ESCALATE-01` `03` `04` `08` 은 **서술 드리프트**로 재분류됐다 (§6.2 `DRIFT-*`). 차단이 아니므로 에이전트가 갱신하고 보고한다.
